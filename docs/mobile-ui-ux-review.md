# 1. 评审结论

当前移动端的整体完成度约为 **7/10**。深墨底、宣纸文字、玉色操作与朱砂危险色形成了统一的武侠视觉语言；场景、出口、人物和物品的组织方式也符合文字 MUD 的核心玩法循环。

目前的主要问题不在视觉风格，而在移动端的**信息优先级、触控可用性、新手引导闭环，以及账号安全带来的信任体验**。

# 2. 现有设计的优势

## 2.1 风格统一且有辨识度

- 墨色背景、纸色文字、玉色操作、朱砂危险色建立了清晰的视觉语义。
- 标题与正文采用具有东方气质的字体组合，避免了常见 Web 工具感。
- 面板、按钮和状态条的层次较克制，整体没有过度装饰。

## 2.2 场景交互贴合文字 MUD

- 九宫格出口将文字方向转化为可理解、可点击的空间结构。
- 人物、物品和场景动作使用 chip 呈现，符合“观察—选择目标—行动”的循环。
- 角色、地图、修炼、对象交互均通过底部 Sheet 承载，主场景不会被复杂功能长期占据。

## 2.3 新手支持已具备基础

- 新手任务有当前步骤、完成进度和后续步骤。
- 角色状态、地图、帮助等常用能力已有入口，具备降低纯文字 MUD 学习成本的基础。

# 3. 问题与改进建议

## 3.1 P0：状态信息缺少语义，且可读性不足

### 现状

顶栏仅显示三条状态的无标签当前数值，字号很小，且未展示上限。玩家无法快速理解数值代表“气、精或内力”，也难以判断当前状态是否危险。

### 建议

- 顶栏至少展示为：`气 390/500`、`精 460/500`、`内 220/400`。
- 低于阈值时同时使用朱砂色、状态文案和图标提示，不依赖颜色表达危险。
- 保留角色面板内的完整状态信息；顶栏承担“快速判断是否需要处理”的职责。

## 3.2 P0：高频点击区域偏小，移动端易误触

### 现状

菜单按钮约为 34px，出口按钮为 40px；人物和物品 chip 的实际高度更小。对于拇指操作，这些尺寸不足以支撑稳定点击。

### 建议

- 所有主操作统一保证最小 **44 × 44px** 点击热区。
- 出口建议提升到 48px，以支持高频移动操作。
- 信息型 chip 可以视觉上保持紧凑，但应通过内边距或透明热区扩大实际可点击范围。

## 3.3 P0：登录凭据的安全与信任体验存在风险

### 现状（已部分完成）

~~线上登录页使用 `http://`；“记住账号和密码”会将账号和密码直接写入浏览器 `localStorage`。~~

- ✅ **已修复**：密码不再存入 `localStorage`；勾选后仅保存账号 ID，密码交由浏览器密码管理器。
- ⏸️ **延后**：HTTPS / WSS 切换属于服务器 Nginx 证书部署，当前不做。

> 在此之前，用户通过不安全的 HTTP 连接输入密码风险仍存在，建议部署时一并解决。

## 3.4 P1：场景和日志双滚动，核心反馈容易丢失

### 现状

主界面同时存在场景区和日志区两个独立滚动容器。战斗结果、任务进展或 NPC 反馈可能被日志滚动掩盖，玩家也不容易判断应在哪个区域继续操作。

### 建议

- 保留场景作为唯一主滚动区。
- 将日志收敛为底部 3—4 行的“动态栏”，点击后展开完整记录。
- 对任务完成、购买结果、战斗危险等关键事件使用 toast 或状态卡即时反馈。

## 3.5 P1：新手任务文案与实际地图入口不一致

### 现状

新手任务提示“使用菜单「地图」”，但当前菜单内没有地图项；地图入口位于场景“出口”区域的右上角。

### 建议

二选一并保持全局一致：

1. 在菜单中加入“地图”；或
2. 将新手任务改为“点击出口区域右上角的地图”。

新手引导中的控件名称、位置和实际界面必须完全一致。

## 3.6 P1：任务条并非真正悬浮，稳定性不足

### 现状

“悬浮任务胶囊”位于日志区域之后的普通页面布局中。场景和日志内容增加时，任务信息的可见性与位置稳定性下降。

### 建议

- 将任务改为固定在底部安全区上方的一行目标条。
- 点击后再展开完整的任务 Sheet。
- 需避免遮挡指令输入框、底部操作和系统安全区。

## 3.7 P1：地图信息过密，ASCII 地图在手机上可读性有限

### 现状

当前地图以约 11px 的 ASCII 字符图展示，需要横向滚动才能完整查看；概念稿中的图形化地图体验尚未落地。

### 建议

- 短期：增加缩放、当前位置固定提示、清晰图例和更明确的可前往标记。
- 中期：改为可缩放的节点地图，让区域、地标和可达方向具备更直接的视觉表达。
- 保持“当前所在地”和“可前往目的地”始终可快速辨识。

## 3.8 P2：菜单中的“挂机”语义模糊

### 现状

“修炼”“挂机”“战斗”等概念在玩家视角中容易重叠，用户无法仅凭名称理解启动后的实际行为和风险。

### 建议

- 根据真实行为改名为“自动修炼”“自动战斗”或“江湖助手”。
- 启动后固定展示：当前目标、进行状态、停止按钮和异常原因。
- 高风险自动行为应提供明确的启动确认与可恢复提示。

## 3.9 P2：登录页缺少进入江湖的记忆点

### 现状

登录页干净、易用，但除标题外缺少世界观表达，首次进入的仪式感不足。

### 建议

不需要堆砌插画，可采用轻量方式增强氛围：

- 极淡的山水纹理或纸墨肌理；
- 每日一条江湖短句；
- 已登录用户的“继续上次闯荡”状态；
- 简短的角色或服务器状态提示。

## 3.10 P2：无障碍与输入反馈需要统一

### 现状

当前缺少统一的键盘焦点样式和减少动效策略；部分状态主要依赖颜色区分。

### 建议

- 为所有可操作控件增加统一的 `:focus-visible` 样式。
- 支持 `prefers-reduced-motion`，减少非必要动画。
- 所有颜色状态均搭配文字、数值或图标表达。

# 4. 建议实施顺序

## 第一阶段：优先解决可用性与信任问题

1. 补全顶栏状态标签、当前值和上限值。
2. 统一高频点击目标至 44px 以上。
3. 修正地图入口与新手任务文案的不一致。
4. 处理 HTTPS/WSS 与“记住密码”的安全体验。

## 第二阶段：优化主游戏循环

1. 将双滚动结构调整为“场景主区 + 可展开动态栏”。
2. 固定新手当前目标条，提升任务可见性。
3. 明确自动修炼、自动战斗等功能的状态与停止路径。

## 第三阶段：提升沉浸感与长期体验

1. 推进手机可读的区域地图与世界地图。
2. 增强登录页的轻量世界观表达。
3. 完成焦点、动效偏好和状态语义等无障碍细节。
